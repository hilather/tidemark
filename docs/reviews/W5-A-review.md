1. **BLOCKER — Temporary descriptor exhaustion permanently disables the watcher.** `crates/tidemark-live/src/watch/mod.rs:205` (especially the unconditional `break` at line 211). Reference: W5-A worker lifecycle and fd-limit review requirement; `07` §3.2. Every read error except interruption terminates the worker and drops its group. A transient `EMFILE` therefore stops monitoring even after another thread releases descriptors. The surviving `Watcher` reports its original mode; the single lossy minute eventually ages out. An unprivileged probe importing the unchanged candidate worker, with only fanotify transport and clock replaced, returned `EMFILE` on the first read and offered an event on the next. Observed: group dropped, exactly one read, loss initially 1 and after 16 minutes 0, overflow count 0, mode still `fd/mount`. Linux's [v4.18 fanotify read implementation](https://raw.githubusercontent.com/torvalds/linux/v4.18/fs/notify/fanotify/fanotify_user.c) propagates descriptor-allocation errors. **Change:** retry transient resource failures with bounded, shutdown-aware backoff, retain truthful degradation while recovering, and ensure an unrecoverable worker exit cannot subsequently appear healthy. Add an injected-error test requiring processing to resume. Evidence: `library/fanotify-worker-probe/{probe.rs,run.log}`. Ref: `finding:w5a-fd-exhaustion`.

2. **SHOULD-FIX — Overflow leaves directory paths cached across missed renames.** `crates/tidemark-live/src/watch/mod.rs:315`; `crates/tidemark-live/src/watch/fidmode.rs:27`. Reference: `07` §§3.2–3.4, overflow recovery and component-wise exclusions. The overflow branch marks a bucket but leaves `HandlePaths` and path-based history intact. Cache invalidation only occurs when a move record is actually processed. If the cache maps a directory handle to `/data/keep`, overflow loses its move into `/data/skip`, and `skip` is excluded, later events resolve metadata through the correct handle but still construct `/data/keep/file`. They pass exclusions and remain wrongly attributed after the lossy minute expires. **Change:** invalidate handle-to-path and other path-dependent history on queue overflow and on loss that could conceal a move; force fresh resolution before applying exclusions. Add a regression that primes the cache, moves the directory across an exclusion boundary, injects overflow, then processes another event. Ref: `finding:w5a-overflow-cache`.

3. **SHOULD-FIX — Backward clock changes mix future buckets into current windows.** `crates/tidemark-live/src/watch/rings.rs:33`, `:80`, `:119`. Reference: `07` §3.3 and W5-A ring arithmetic tests. `advance` ignores a backward timestamp, `add` always selects the newest bucket, and window queries have only a lower timestamp bound. The actual candidate ring in a standalone harness, given +10/+20/+30 at seconds 60/120/180, returns 60 for `hot(60, 1)` after rollback instead of 10. Adding +5 at second 60 then makes minute 180 report 35. This is neither timestamp-correct nor marked approximate. **Change:** implement an explicit rollback policy preserving minute attribution and drain-once semantics (or reset affected history with a loss indication), and bound queries to the intended interval. Test `add`, `hot`, `lossy`, and `drain` during rollback. Existing tests only call backward `advance` and then query at the old future time. Evidence: `library/rings_review_probe.rs`, `rings_review_rollback_test.log` (expected regression failure, actual 60 versus expected 10). Ref: `finding:w5a-clock-rollback`.

4. **SHOULD-FIX — Foreground watch does not exclude the configured state directory.** `crates/tidemark-cli/src/cmd/watch.rs:47`. Reference: `08` §3, `[watch]`: state_dir is always excluded; W5-A review safety requirement. Options contain only explicit `watch.exclude_prefixes`, whose default is empty. The processor only checks those prefixes and its own PID. Thus `watch --mount /` records writes to `general.state_dir` by a separate daemon, CLI, or maintenance process. **Change:** add the configured state directory to the component-wise exclusions when assembling watcher options, resolving its actual path when available, and test state writes from a different PID plus a similarly named sibling directory. Ref: `finding:w5a-state-exclusion`.

7. **SHOULD-FIX — CLI mount paths are normalized before realpath.** `crates/tidemark-cli/src/cmd/watch.rs:38`. Reference: `08` §1.1 and `13` Query paths/SCR-004. `RawPath::from_path` performs lexical normalization before any canonicalization. This does not require relaxing the watcher's no-follow rule. Ref: `finding:w5a-mount-canonicalization`.
