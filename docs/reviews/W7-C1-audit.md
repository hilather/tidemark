### F01 — BLOCKER — Root state writes trust unverified directory ancestry and SQLite leaves

Reference: `finding:w7-c1-f01`.

Primary sites: `crates/tidemark-store/src/timeseries.rs:32-50,95-107`; `crates/tidemark-scan/src/orchestrator.rs:641-654`; `crates/tidemark-store/src/writer.rs:32-61`. Deployment ingress: `crates/tidemark-cli/src/deploy/real.rs:87-98`; `crates/tidemark-cli/src/deploy/files.rs:205-255`; `crates/tidemark-cli/src/deploy/mod.rs:367-369`.

The scan lock's `O_NOFOLLOW` protects only `scan.lock`; recursive creation and state ancestor traversal follow symlinks and do not verify existing directory ownership or modes. `Catalog::open` recursively creates state then passes `state_dir/timeseries.db` to a header `File::open` and to SQLite. Neither caller establishes regular-file/no-follow/single-link provenance before opening; in particular, the header open can follow a symlink or block on a FIFO before SQLite examines it. Snapshot construction creates a private exclusive file but drops its descriptor and then reopens its pathname with SQLite. An existing snapshot directory is not verified as private.

This is reachable through implemented direct CLI code, independently of the daemon stubs: `crates/tidemark-cli/src/cmd/scan.rs:59-70` opens the writable catalog before scanning. The same sinks are used by writable catalog commands. A forged state marker is not proof of root provenance: production installation skips its `0700 root:root` requirement whenever reading the marker succeeds; `private_dir` accepts the marker's public format and path fields, then chmod/chowns the directory. It does not sanitize descendants. The existing `deploy` child is not checked for ownership/mode either.

Concrete scenario: an administrator configures a custom state directory below an unprivileged user's writable directory. That user can precreate a matching marker and a `timeseries.db` symlink to a root-owned empty file or compatible SQLite database outside Tidemark state. Stage accepts the marker, makes the top directory private, and retains the malicious leaf. A subsequent root direct scan opens the external target through the symlink; an empty target passes the header check and is initialized/migrated, violating the state-only write guarantee. A precreated FIFO can instead block the unbounded-time header open. Even an initially clean root-owned state directory beneath an attacker-owned ancestor remains replaceable by renaming its ancestor, so final-directory mode alone is insufficient. These scenarios require an unsafe/custom state location or preseeded state; the default `/var/lib/tidemark` under trusted root-owned ancestors does not give an ordinary user an entry point.

Exact recommended change: introduce a shared verified state handle; walk ancestry with no-follow descriptors and check who can replace each directory entry, allowing sticky `/tmp` only when the relevant child is protected against the untrusted user. Require trusted ownership/private permissions for existing state and its writable subdirectories; do not accept an attacker-authored marker as ownership evidence. Refuse state leaf symlinks, nonregular files and unexpected hard links; ensure SQLite's main and sidecar opens cannot follow replaced leaves, and keep write/publish/remove operations anchored to the same verified directory handle. Preserve unprivileged fixtures by validating against the effective owner rather than hardcoding root in library code. A complete implementation must handle SQLite's pathname-based opening explicitly, not only pre-stat a leaf. Add adversarial temp-directory tests for forged markers, symlink/FIFO/hardlink leaves, retained writable descendant handles, and ancestor renames.

Touched files for the fix: `crates/tidemark-cli/src/deploy/files.rs`, `crates/tidemark-cli/src/deploy/real.rs`, `crates/tidemark-cli/src/deploy/mod.rs`, `crates/tidemark-cli/src/deploy/tests.rs`; `crates/tidemark-scan/src/orchestrator.rs`; `crates/tidemark-store/src/catalog.rs`, `crates/tidemark-store/src/timeseries.rs`, `crates/tidemark-store/src/writer.rs`, `crates/tidemark-store/src/reader.rs` (reader shares pathname trust), `crates/tidemark-store/tests/storage.rs`; `crates/tidemark-store/src/state_dir.rs` (new safe shared state-handle module), `crates/tidemark-store/src/lib.rs` (module declaration), `crates/tidemark-store/src/space_guard.rs`, `crates/tidemark-cli/src/cmd/snapshots.rs`, and `crates/tidemark-cli/src/deploy/purge.rs` for retained-handle accounting/removal. Existing crate dependencies suffice for this placement. The attempt baseline’s later R3-15 records SQLite pathname leaf opening as an unresolved risk; it is not fixed in this candidate. A separate SCR may be needed for any shared public API addition.

### F02 — SHOULD-FIX — Deployment validates different configuration bytes from the bytes installed

Reference: `finding:w7-c1-f02`.

Sites: `crates/tidemark-cli/src/deploy/mod.rs:120-130,294-315,376`; `crates/tidemark-core/src/config.rs:685-697`; related marker readers `crates/tidemark-cli/src/deploy/files.rs:153-155` and `crates/tidemark-cli/src/deploy/purge.rs:110-114`.

`Env::source` reads byte string A using the bounded no-follow reader, separately reopens the pathname through `Config::load` to parse B, then checks that another bounded read equals A. An attacker able to replace or change the source can present A/B/A: preflight checks B, yet the installed configuration and recorded hash describe A. The middle reopen follows symlinks and can also block on a replacement FIFO, despite the bounded/nonblocking safe reader used around it. This is a concrete check/use race, not prevented by the two equal endpoint reads. Marker-root and purge config checks likewise inspect a pathname and reopen it through `Config::load`.

Recommended exact change: implement the already-decided R3-6 `Config::from_toml_bytes(&[u8])` parser, with the same 1 MiB bound, UTF-8/TOML/default-merge behavior and error precedence; make source load once through the verified descriptor reader and use exactly that vector for parsing, installation and hashing. Change marker/purge configuration reads to the same one-read parser. Keep the installed destination directory descriptor through publication and compensation rather than reopening it by path. Tests should deterministically change the source between former reads and prove the installed bytes are precisely the validated bytes; also cover replacement by FIFO/symlink.

Touched files: `crates/tidemark-core/src/config.rs`; `crates/tidemark-cli/src/deploy/mod.rs`, `crates/tidemark-cli/src/deploy/files.rs`, `crates/tidemark-cli/src/deploy/purge.rs`, `crates/tidemark-cli/src/deploy/tests.rs`. Later R3-6 is normative context only: the candidate demonstrably still has the older triple-read implementation.

### F03 — SHOULD-FIX — Symlink analysis can write symlink atimes

Reference: `finding:w7-c1-f03`.

**Sites:** `crates/tidemark-fs/src/symlinks.rs:248,259`; directory protection at `:73–82` does not cover the symlink inode.

`readlinkat` obtains link text without opening its referent, but it can update the link's own atime. The parent directory's `O_NOATIME` does not suppress that update. An ordinary user can create many old symlinks under a scanned root on a relatime/strictatime mount; `tidemark symlinks` then causes metadata writes while promising metadata-only, read-only analysis. The optional target check also follows target chains for stat and can encounter links on other mounts. This is a metadata-write issue, **not a regular-file content read**.

A local unprivileged temporary-fixture experiment opened the parent with `O_RDONLY|O_DIRECTORY|O_NOFOLLOW|O_NOATIME`, then read one link with `readlinkat` semantics. Its atime changed from `1000000000` to `1791863614733465135` ns on kernel `7.2.5-3-omarchy`; the payload file was never read. Artifact: `library/readlink-atime.json`. This establishes the syscall behavior locally, not a Rocky guest test result.

**Recommended change:** resolve the contract explicitly. To preserve the absolute no-metadata-write promise, refuse link-text reads on mounts without `noatime`, and refuse target-chain following unless every resolved component's mount is verified to suppress atime before any follow/readlink operation. Do not remount anything, modify atimes back, or assume adding `O_NOATIME` to an `O_PATH` descriptor solves it. If full existing `--check-targets` behavior cannot be preserved under that restriction, submit a spec-change request for a narrowly documented atime exception or restricted behavior; do not silently weaken the frozen guarantee. Add strictatime/relatime/noatime guest tests measuring **link and directory** atimes separately. Touch `crates/tidemark-fs/src/symlinks.rs`, `crates/tidemark-cli/src/cmd/symlinks.rs`, `crates/tidemark-fs/tests/w3b.rs`, and, only after an accepted SCR, `docs/plan/03-link-semantics.md`, `docs/plan/08-interfaces.md`, `docs/plan/12-decisions-and-risks.md` and `docs/security.md`. No SCR or implementation change is made in this report-only task.

### F04 — SHOULD-FIX — Scan setup follows replaceable ancestor symlinks

Reference: `finding:w7-c1-f04`.

**Sites:** `crates/tidemark-scan/src/orchestrator.rs:684–689`, called at `:116–123` and used for metadata probes at `:125–159`.

### Kernel layouts and returned counts

`sys/src/gen/bindings.rs:187–267` checks sizes/alignments and field offsets for every hand-transcribed XFS structure used here: bstime 16/8, bstat 136/8, bulkreq 32/8, geometry v1 and geometry 112/8, bulk_ireq 64/8, bulkstat 192/8, and flexible-array request 64/8. Inspection of the repr(C) field definitions agrees with those expected offsets, including 64-bit alignment padding in the legacy structs, 32-bit v5 link count at 112, mode at 132, extents64 at 136, and zero-length records at offset 64. The ioctl encoding tests pin 0x80705864 for geometry v1, 0xc0205865 for legacy bulkstat and 0x8040587f for v5. `04-scanner.md:278` records the same independent C measurements. This audit did not remeasure against guest XFS headers; none is installed locally. The v1 record's 16-bit link count is never used for metadata scanning: v1 is probe-only, production bulk enumeration uses v5.

`sys/src/fanotify.rs:398–435` checks Metadata 24/8 with offsets 0/4/6/8/16/20, InfoHeader 4/2, InfoFid 12/4, and HandleHeader 8/4. Byte-based parsing avoids casting unaligned event buffers. The layouts, flag values, record kinds 1/2/3 and version 3 agree with the local `/usr/include/linux/fanotify.h` inspected read-only (not guest validation). Length guards precede each integer extraction; event and info counts are bounded by returned slice, information record length is u16, handle bytes <=128, and DFID names require a terminator. Negative event fd means no fd to own. Unknown info kinds are skipped only after length validation. Metadata truncated below 24 bytes cannot be interpreted; a valid-length rejected record is skipped and the next record remains available. Error/abandoned-batch descriptor closure has a specific test at `fanotify.rs:514`; malformed-length and truncated-FID tests are at :438 and :465.

The v5 batch memory bound is <32 MiB for kernel+converted buffers, with 65,536 maximum entries. The existing tests cover invalid batches, arithmetic overflow, duplicate/order/range rejection, unsupported ioctl behavior and permission errno. They do **not** inject an oversized successful ocount, a short successful payload, a nonadvancing successful cursor, or an invalid private request buffer size into the FFI helpers. Add such mock-kernel cases in the later fault/fuzz task; no test was run here.

## Fanotify ownership / unread-close result

`Fanotify::read` reads the notification-group fd. `decode` adopts the event fd as `OwnedFd` before metadata validation (`tidemark-sys/src/fanotify.rs:277–286`), so validation failures after that adoption, overflow classification and yielded events drop the fd. `EventIter::drop` drains remaining valid records (260–264). The watcher collects at most the 64 KiB batch into `Vec<Result<RawEvent>>`; breaking on shutdown drops unprocessed owned events (`watch/mod.rs:248–269`). The process's own PID early return also drops its event fd; fdmode resolution returns copied metadata/path so the fd closes on match-arm exit (`watch/mod.rs:479–485`). Thus valid kernel event batches close event descriptors unread on success, error and early-stop paths. If a fabricated/truncated record gives no traversable frame length, iteration discards the remaining bytes: the all-record cleanup claim presupposes the documented kernel framing. Pure-parser fuzzing must not manufacture live arbitrary fd numbers; fd ownership is not an arbitrary byte-parser contract.

## Guest strace test design — pending implementation and VM run

Implement `tests/fault/content_reads` under `--features privileged`; invoke the test once on each Rocky 8.8/8.10 guest in its host mount namespace. The harness creates a disposable `test_support::xfs::LoopXfs` fixture, confirms v5 bulkstat eligibility, writes test inputs before tracing, and keeps configuration/state/traces **off the scanned XFS mount**. No setup/fixture-generator process is a child of strace. Use a unique root-owned 0700 work directory, the mounted XFS root as `AUDIT_MOUNT`, the absolute built binary as `AUDIT_BIN`, and work as `AUDIT_WORK`. All are test harness values; none points at a production mount. Do not run the test in a private mount namespace: Watcher::namespace_ok intentionally rejects it.

Fixture: nonempty regular files, sparse file, hard links, symlink to regular file, symlink to an outside regular sentinel, directory symlink, dangling/looping symlinks, names with LF/TAB/ESC/invalid UTF-8, and a separate directory-to-symlink rename-race scenario. Keep the main coverage runs quiescent except for the separately specified writer activity; run rename churn only in separate race trials. Record `(dev,ino)` for every regular payload including outside sentinels and hard-link aliases. A **separately spawned, untraced** helper keeps a deleted regular file open and grows a live file through an O_WRONLY descriptor, with an explicit readiness handshake. It creates/closes a write fd repeatedly during watching (growth on a single permanently open fd is insufficient for CLOSE_WRITE). Trace only the CLI and its descendants. Watcher readiness must be observed before emitting required events, and the watch JSON must contain that helper's events; an empty event run cannot pass.

The following shell is the exact command interface to run once harness paths exist. It uses broad syscall classes so `open`/`openat`, descriptor duplication, close, mmap, directory reads and future alternative reads are not accidentally omitted. Rocky guest strace support for these classes must be checked as a prerequisite; unsupported tracing is a test failure/infrastructure error, never a pass.

```bash
set -euo pipefail
export LC_ALL=C
trace_case() {
    local case_name="$1"
    shift
    strace -ff -ttt -yy -xx -s 131072 -v \
        -e trace=%file,%desc,%process,%memory \
        -o "$AUDIT_WORK/$case_name.trace" \
        "$AUDIT_BIN" -c "$AUDIT_WORK/config.toml" --json "$@" \
        >"$AUDIT_WORK/$case_name.json" 2>"$AUDIT_WORK/$case_name.stderr"
}
trace_case walk scan "$AUDIT_MOUNT" --mode walk --threads 2 --throttle max
trace_case bulk scan "$AUDIT_MOUNT" --mode bulk --threads 2 --throttle max
trace_case phantom phantom --direct --mount "$AUDIT_MOUNT"
trace_case writers writers --direct --mount "$AUDIT_MOUNT" --interval 2s
trace_case symlinks symlinks "$AUDIT_MOUNT" --check-targets --limit 100
trace_case watch watch --mount "$AUDIT_MOUNT" --events close_write,modify &
watch_trace_job=$!
# Harness waits for fanotify mark/readiness, emits writes via its untraced helper,
# waits for expected watch JSON, then sends SIGTERM to the traced tidemark PID
# found in execve (NOT to strace and NOT the process group).
wait "$watch_trace_job"
```

The harness timeout must kill/reap the strace process and CLI if readiness or output never arrives. Quiescent walk/bulk coverage runs must exit successfully and their snapshot metadata must say the requested mode (`bulk` forced mode must not silently fall back); phantom must include the deleted fixture holder, writers must include growth, symlink output must include the outside/loop cases. Run a second watcher shutdown trial immediately after queueing many events so a partially processed batch is exercised. Run the rename-race cases separately: documented race/refusal exits are permitted, but hangs, payload reads and unexplained crashes still fail. Symlink analysis can correctly refuse after a directory identity changes, so a race case must not require its successful completion.

The assertion is **not** “no read of any regular file”: the executable loader, config and SQLite legitimately read regular files. A trace checker must parse unfinished/resumed records, track process/thread fd tables (`clone(CLONE_FILES)`, fork copy), and handle `open/openat`, `dup*`, `fcntl(F_DUPFD*)`, close/reuse, exec CLOEXEC, exit and memory mappings. Distinguish the private fanotify group fd by `fanotify_init` and decode every successful group `read` result as native-endian fanotify metadata using the known 24-byte header. Every nonnegative event fd enters the table immediately, despite having no open syscall. A 131072-byte strace string limit exceeds the watcher's 65536-byte buffer; any truncated/unparseable required payload fails the test. Track such fds until close/reuse or process exit. Require **explicit close** for received event fds before normal shutdown, not merely cleanup by process exit. Resolve relative/dirfd paths against tracked cwd/fd identities; use `-yy` annotations as supporting evidence, not the sole provenance source. A trace of successful `fstat/statx` or helper manifest binds fixture `(dev,ino)` to fd identity, catching hard-link aliases and ` (deleted)` cases.

For every `read/readv/pread64/preadv/preadv2` (including failed calls and zero-byte results), sendfile/copy_file_range/splice input descriptor and every file-backed mmap with read/execute permission: reject access to a fixture payload inode or an event descriptor; reject any unclassified regular-file source. Directory `getdents*`, readlink/readlinkat, stat-family and the group read are metadata exceptions. Also assert that walker/bulk do not open fixture regular files for data access (O_PATH is harmless) and event fds only receive allowed metadata/path/close operations. Extend instrumentation to reject alternative payload routes such as io_uring_setup or unsupported descriptor transfer rather than silently classifying them as harmless.

Allowlist exact config path and freshly created private state directory (and SQLite-created sidecars), fixed procfs metadata suffixes above, numeric sysfs block metadata, plus loader/library files actually identified as root-owned guest runtime dependencies before the test (including /etc/ld.so.cache). Do not allowlist arbitrary `/proc/**`: `/proc/PID/fd/N` can read a payload if opened. Do not allowlist all `/usr`, `/etc`, `/tmp`, test-support processes or filenames ending in `.db`. Any legitimate additional runtime/config file must be added narrowly with an explanation. All regular-file payload fixture inodes override the allowlist, even if hardlinked beneath a nominally allowed directory. Store raw traces, command statuses, fixture inode manifest, runtime allowlist and machine-readable assertion counts. At least one group read with a regular-file event fd, one proc descriptor matching the deleted/growing fixture, and a v5 bulk ioctl must be observed for coverage.

Suggested checker regression cases: reuse an event fd number for a permitted config file after close; duplicate a forbidden fd; use an outside symlink/hard-link alias; child process inherits a forbidden fd; malformed/truncated trace; successful empty watcher; deliberate helper binary that opens+reads the sentinel (checker must fail); mmap sentinel (checker must fail). These validate the trace oracle, not product behavior.

What this design does not prove: hostile root/kernel/VFS compromise, arbitrary dependency source behavior, scanner safety on an untested kernel, or secure state/config ancestry. It supplies the requested guest assertion for actual executed scanner paths. No VM trace, build or test was run in this review.

## Output escaping assessment

The implemented human tree/files/diff/links/symlink/watch/writers/phantom paths use `RawPath::display_lossy` or `display_lossy_bytes`: `tidemark-core/src/path.rs:253–282`, `tidemark-cli/src/render/tree.rs:112,197`, `render/diff.rs:63–104`, `render/links.rs:65–120`, `render/symlinks.rs:24–37`, `cmd/watch.rs:214–222`, `cmd/writers.rs:47–49`, `cmd/phantom.rs:39–43`. The common function escapes control characters, backslashes and invalid UTF-8 bytes; ESC, LF and TAB therefore cannot become terminal escape sequences or extra rows through those paths. `RawName` rejects slash/NUL/dot/dot-dot and `RawPath` retains normalized bytes and component-wise prefix checks (`path.rs:18–32,63–88,127–132`). Printable Unicode is retained, including format/bidirectional characters not recognized by `char::is_control`; the display is not a defense against every visual-confusability trick. That is a documented residual presentation limit, not a demonstrated terminal-control bypass.

JSON uses `serde_json::to_writer` (`render/mod.rs:15–23`) and `path`/`path_b64` adapters (`path.rs:173–190,247–251`). JSON quoting prevents raw ASCII controls from breaking framing; base64 preserves non-UTF-8 names. Consumers must still escape decoded strings when putting them in terminals or HTML. Serialization is not redaction.

Journal alert subjects derived from paths are escaped at `tidemark-live/src/alerts/rules.rs:117,141,190,224–225`; `JournalDeliver` writes structured fields at `alerts/deliver.rs:48`. Rule names/message text originate in trusted configuration and are interpolated without universal terminal escaping (`alerts/mod.rs:179–189`). Watcher startup logs use escaped mount names (`watch/mod.rs:190`). Some administrative/error paths use `Path::display`, e.g. catalog-recovery logging (`scan/orchestrator.rs:677`), so an absolute claim that **all** log text is escaped is not supported. The daemon's actual journald wiring, API rendering and metrics textfile escaping cannot be evaluated: their candidate implementations are stubs. The future textfile exporter must escape backslash, double quote and newline per label syntax, bound cardinality, and avoid leaking raw control bytes. This review does not claim those protections exist here.

## Proposed docs/security.md

The following fenced document is the proposed complete file. It describes the required **post-HTTP-removal** v1 posture, includes unresolved audit limitations, and does not claim the candidate's stub daemon implements that posture.

```markdown
# Tidemark security model

Tidemark collects disk-usage metadata on a host whose operating system, kernel and root administrators are trusted. Ordinary local users and application processes may control filenames, directory structure, links, process names and workload activity. Their data is untrusted input to a privileged observer. Tidemark is not a deletion tool, a database-content inspector, or an authorization system.

This document describes v1 after ADR-020 removes all HTTP: metrics are written only to a textfile and alerts only to the journal. There is no HTTP listener, webhook, outbound HTTP client or network socket for serving measurements. Local control uses a Unix-domain socket. The unit permits only AF_UNIX and AF_NETLINK; permission to use a family is not a claim that every process uses it. Remove the HTTP/TLS dependencies along with the code. PostgreSQL-specific tracking is excluded from v1 under ADR-019.

## Privileged process and confinement

The production daemon runs as root with `NoNewPrivileges=yes` and exactly `CAP_SYS_ADMIN CAP_DAC_READ_SEARCH CAP_FOWNER CAP_SYS_PTRACE` in its capability bounding set. SYS_ADMIN is needed for bulk XFS metadata and privileged fanotify operations. DAC_READ_SEARCH permits complete directory traversal and, where supported, file-handle lookup. FOWNER permits O_NOATIME on directories owned by other users. SYS_PTRACE permits cross-process procfs inspection. The supplied Rocky 8.8/8.10 measurements exercised this set with a 2 GiB memory limit and reported systemd-analyze security 5.9 MEDIUM; they are platform observations, not a proof that every build or configuration is secure.

Dropping SYS_ADMIN requires disabling bulk and watcher features; dropping DAC_READ_SEARCH limits readable coverage; dropping FOWNER can introduce directory-atime writes; dropping SYS_PTRACE limits process attribution. Such reduced profiles require explicit coverage reporting and guest tests. For the full feature set, a small privileged helper could narrow long-lived privileges in a future design. There is no such privilege split claimed for v1.

The watcher must remain in the host mount namespace. ProtectSystem, ProtectHome, PrivateTmp and related systemd settings that create a private mount namespace can make fanotify marks observe different mount objects. The watcher checks its namespace against PID 1 and refuses an incompatible namespace. Namespace restrictions, capability bounds, native syscall architecture and personality/realtime restrictions reduce exposure, but they do not create a read-only filesystem sandbox. Root with these capabilities can damage host data if the program is compromised. The product's read-only design must never be described as a kernel-enforced guarantee against arbitrary code execution.

## Access, sudo and sensitive output

There is no `tidemark` group. Installed config, snapshots, temporary snapshot databases and the API socket are root:root 0600; state/runtime directories are root:root 0700. Every API method must authenticate the kernel-reported peer uid using SO_PEERCRED and accept only uid 0, including when an unprivileged fixture runs its own daemon. File ownership is the ordinary CLI boundary; running an unprivileged CLI against production files fails with the normal error and a sudo hint, rather than a separate uid-based exit policy.

Administrators use `sudo tidemark ...`. Keep configuration, installed binaries, service files, the state directory and every replaceable ancestor under trusted administration. Do not treat a matching state-marker JSON file as proof of origin. Never give an untrusted user a broad sudo rule permitting arbitrary Tidemark configuration, state, deployment or output paths. A delegated reporting wrapper must select fixed trusted configuration and commands and must be reviewed as a root interface. Do not make production state world-readable to enable convenience access.

Path names can reveal customer identities, project names, database locations, users and operating activity even when no payload is read. Snapshots, catalog/time-series data, command exports, API responses, metrics labels and journal events can carry those names and associated sizes, times, PIDs, units or alert subjects. Escaping preserves safety of representation; it does not anonymize or redact data. Protect backups, exported reports, traces and screenshots accordingly. A metrics collector that republishes the textfile exports this sensitive metadata under its own access policy. Arrange collection without silently widening Tidemark's root-only state/config/socket permissions. The metrics directory and staging files must not be writable by untrusted users.

Human path rendering escapes control characters, backslashes and invalid UTF-8. Process comm and unit names are labels, never commands. JSON preserves valid UTF-8 with JSON escaping and uses path_b64 for arbitrary non-UTF-8 paths. Consumers must escape decoded values for their own output context. Printable Unicode can remain visually confusable. Metrics require Prometheus label escaping for backslash, quote and newline and bounded series selection. Journal path subjects are escaped structured fields; configuration-derived rule/message text must also be treated carefully by viewers. Do not assume every downstream terminal, JSON consumer or logging sink neutralizes control text automatically.

## Metadata-only observation and read-only behavior

Walker directories are opened component by component with O_DIRECTORY and O_NOFOLLOW. Entry attributes use no-follow stat operations; directory enumeration uses getdents. Bulk scanning reads XFS inode metadata through bounded ioctls and joins it to the observed namespace. It never opens scanned regular files for content. Procscan reads fixed procfs metadata and stats or reads the text of `/proc/PID/fd/N` links; it never opens those links as payload streams. Fanotify group reads contain notifications. Kernel-issued event file descriptors are only used for metadata/path resolution and are closed unread. File-handle resolution uses O_PATH. Symlink analysis reads link text and optionally target metadata, not regular-file payloads.

Procfs, sysfs, explicitly selected configuration and Tidemark's own SQLite state are separate legitimate reads. Their descriptor provenance matters: a generic regular-file read of a supposedly internal state path is unsafe if a hostile ancestor or leaf can redirect it. SQLite main, journal/WAL/SHM files, snapshot staging files, locks and publication/removal operations must remain anchored in verified state. Symlinks, nonregular artifacts and unexpected hard links must be refused at those boundaries. No-follow preflight checks alone do not eliminate a subsequent pathname race.

The scanner issues no writes to observed regular files, does not change their ownership, permissions, quotas or xattrs, and does not remount filesystems, edit fstab/boot configuration or change LVM. LVM integration invokes only reporting commands `lvs` and `vgs`, with bounded output and timeouts; it does not use `--readonly`, which omits required thin-pool information. Tidemark writes its own state and generated output artifacts; deploy explicitly installs its config and changes the tidemarkd service state. Those intentional writes must not escape their verified destinations.

O_NOATIME on directory descriptors avoids directory-atime writes; EPERM fallback is measured and reported and cannot promise unchanged atimes. Reading symlink text or following target chains can update **symlink** atimes even when the parent uses O_NOATIME. The W7-C1 audit demonstrated this on a local temporary fixture; Rocky strictatime/relatime/noatime validation and a contract-compliant restriction or explicit approved exception remain necessary. Until that issue is closed, do not claim an unconditional absence of all metadata writes for symlink analysis.

Existing mount points, including same-device bind mounts, are skipped using mountinfo; opened descriptors are checked for device, available mount ID and expected inode before enumeration. Name rereads recheck descendant components. Supplied Rocky measurements report no statx mount ID on the tested 8.8/8.10 kernels. A late same-device bind retaining the same inode cannot be distinguished by the existing fallback checks. Host mount changes are privileged operations. Optional symlink target diagnosis follows metadata outside the root by design and must not be represented as ordinary no-follow traversal. No payload read follows from that diagnostic feature.

## Availability, attribution and consistency limits

Channels, event buffers, directory records, task paths, process inventories and caches have count or byte caps. Directory traversal and aggregation avoid recursion proportional to tree depth. Scans use a Gate for metadata work and an adaptive controller to protect other disk workloads; procfs reads are exempt because they are kernel metadata rather than disk scan I/O. Scans are serialized per host. These measures reduce impact but cannot guarantee an application's latency on every workload.

Some aggregate memory admission is estimated. Count caps do not ensure all long names or process targets fit a byte budget; the correctly parsed systemd memory limit is the final whole-process backstop. Local users can force expensive traversal, cap refusals, event overflow and incomplete attribution. They can create misleading comm/cgroup labels and race renames, PID reuse or open-file changes. PID/starttime and inode/device rechecks reduce misattribution, but reports are observations, not transactionally consistent snapshots or security identities. Lossy, degraded, unavailable and partial results must remain visible; an unavailable measurement is not zero.

## Deployment and rollback

`deploy stage --from FILE` must parse, validate, install and hash the same single bounded no-follow read. Preflight rejects unsafe state paths, symlink/nondirectory ancestry, mount roots, state directories containing protected system locations or tracked roots, and malformed or mismatched deployment artifacts. Existing state, descendants and every ancestor capable of replacing them need trusted provenance; an attacker-written marker is insufficient. Retain verified directory handles through service actions, publication and compensation, including the installed configuration destination.

Blocking preflight failures make no host changes. After preflight, failed publication or service actions trigger best-effort compensation of previous config/marker/staged bytes and enabled/active state. This is not a transaction: downtime, timestamps and newly created empty directories can remain. Stage enables without starting unless `--start-now` is explicitly requested. Unstage stops/disables and retains state by default. `--purge-state` requires explicit confirmation and guarded, iterative no-follow removal with mount/identity checks. It is destructive only to the verified Tidemark state tree; a marker does not authorize arbitrary directory deletion. Tidemark never edits boot-critical filesystem/LVM configuration.

The exact W7-C1 audited tree still has unsafe custom-state/SQLite-path trust, a multiple-read deployment-config race and a scan-setup ancestor-following gap. These are not mitigated merely by root ownership of the final state directory. Use the report's repair and regression requirements before treating custom writable ancestry or preexisting state as safe.

## SELinux

Tidemark ships no SELinux policy module and does not change SELinux mode or policy. The supplied Rocky 8.8/8.10 guest observations used Enforcing and reported no denials; the deployment context is unconfined-service operation, not a Tidemark-specific mandatory-access-control boundary. The owner's production hosts do not run Enforcing. Enforcing, Permissive and Disabled must not be confused with different product read-only guarantees. Recheck labels, service execution and audit denials on each supported guest and deployment layout; successful earlier tests do not promise a future policy/image will behave identically.
```
