**BLOCKER — The mount device is not always a regular file's device.** `finding:w8-review7-procfs-nonuniform-dev`; `crates/tidemark-fs/src/procfs.rs:384–386`, with device-only map construction at `311–326`.

The prefilter treats a known mountinfo device outside `devs` as proof that its descriptor cannot have a watched `st_dev`. That assumption fails for an OverlayFS mount with layers on different filesystems and `xino=off`: a regular upper file can report the upper filesystem's device, while its fdinfo mount ID identifies the overlay mount. Put upper/work on watched XFS and the lower layer on another filesystem, then create and keep a writable file open through the overlay. The new filter discards it on every pass before metadata can recognize XFS. Unlinking that file can also hide its phantom usage. The base implementation reaches the metadata check. This scenario follows the [kernel's OverlayFS inode-property documentation](https://docs.kernel.org/filesystems/overlayfs.html) and [Linux 4.18 `ovl_map_dev_ino`](https://raw.githubusercontent.com/torvalds/linux/v4.18/fs/overlayfs/inode.c); it is not a claim that every overlay configuration exposes the underlying device.

A diagnostic using the candidate's complete `scan_open_files` reproduced the underlying assumption failure without mounts: a 12,345-byte deleted-open file in this host's Btrfs-backed attempt output had mount ID `1064`, mountinfo device `0:30`, metadata device `0:54`, and `nlink=0`; scanning for its actual device omitted the held descriptor. Btrfs demonstrates the code path, not the XFS/OverlayFS runtime gate. Preserve enough mount information to restrict negative filtering to filesystems with a justified uniform device identity; fall back to metadata for the others. Add an XFS-backed overlay regression in a VM.

**BLOCKER — Cached mount-ID reuse can suppress watched files.** `finding:w8-review7-procfs-stale-mount-id`; `crates/tidemark-fs/src/procfs.rs:349–350` and `384–386`.

An early PID populates the namespace cache with mount ID M on an unwatched device. During the same inventory, that mount is fully unmounted and freed, and a bind mount of watched XFS is allocated M in the same namespace. A later PID has a stable descriptor on the new mount. The unchanged namespace key returns the old map; M is known, so the unknown-ID fallback never runs and the descriptor is discarded before either metadata check. Linux 4.18's allocator explicitly makes freed mount IDs reusable; see `mnt_alloc_id`/`mnt_free_id` in [the kernel source](https://raw.githubusercontent.com/torvalds/linux/v4.18/fs/namespace.c). An inventory-scoped cache limits duration but does not validate its negative answers.

The diagnostic supplied an old unwatched mapping and a stat callback that would identify the watched device: the callback was never called. This proves the candidate's decision for stale input; actual mount churn was not executed. Invalidate or revalidate negative cache decisions against mount topology, with a conservative fallback when freshness cannot be established. Test reused known IDs, not only newly unknown IDs. Namespace inode reuse and namespace changes during lookup also lack an identity pin/revalidation; no separate runtime finding is claimed for those races.

**BLOCKER — Reused descriptors can carry another file's access flags.** `finding:w8-review7-procfs-fd-flags`; `crates/tidemark-fs/src/procfs.rs:426`, `441–445`, and `450–458`.

The first fdinfo read now precedes the first stat. Read fdinfo for read-only file A, then let the process replace that descriptor with writable file B before metadata is read. Both stats and readlink describe B and pass the device/inode check, but the accepted flags still come from A. The second fdinfo is only used for mount filtering. `crates/tidemark-live/src/procscan.rs:255–263` consequently omits a linked writable B; reversing the modes can falsely classify a reader as a writer. In the base, flags were read between the two metadata calls, so a different-inode replacement across those observations was rejected.

A deterministic diagnostic used real temporary files and actual descriptor-number reuse, then the candidate's parsing/filter helpers in the same observation order. B passed the metadata check while retaining A's read-only flags. Bind accepted flags to a read within the metadata validation interval, and add this interleaving regression. Same-inode replacement and changes after the final observation remain best-effort limitations.

**BLOCKER — Typed allocation failures are swallowed by `per_fd`.** `finding:w8-review7-procfs-typed-oom`; `crates/tidemark-fs/src/procfs.rs:139–150`, reached from `426` and `450`.

Only raw ENOMEM/EMFILE/ENFILE survive. `bytes()` at `95–99` uses `File::take(...).read_to_end()`, which can return `ErrorKind::OutOfMemory` without a raw errno when buffer growth fails. The pinned [Rust 1.98 reader](https://raw.githubusercontent.com/rust-lang/rust/1.98.0/library/std/src/io/mod.rs) calls `try_reserve`; [its error conversion](https://raw.githubusercontent.com/rust-lang/rust/1.98.0/library/alloc/src/io/error.rs) produces this typed error. An fdinfo allocation failure therefore skips that file and can yield `Ok` with incomplete measurements, bypassing daemon resource retry. The mapping path similarly falls back on typed OOM instead of aborting.

The diagnostic converted a fallible reservation error to `io::Error`, checked that its kind was OutOfMemory with no errno, and confirmed both the descriptor skip and mapping fallback. It did not exhaust host memory. Preserve typed OutOfMemory in addition to the specified raw errors and test both representations. Cache-budget errors already propagate directly and do not have this problem.

**BLOCKER — Final process validation still converts resource failure into partial success (pre-existing).** `finding:w8-review7-procfs-final-starttime`; `crates/tidemark-fs/src/procfs.rs:477–478` (base `340–341`).

`read_starttime(pid).ok()` erases every error. For example, if opening the last process's final stat record fails with EMFILE after its descriptors have been collected, the code truncates those records and returns the other processes as a successful inventory. No subsequent operation must fail, so the daemon need not enter its retry/error path. This is unchanged by the patch, but remains within the requested candidate-tree and resource-policy review. It is classified as wrong data, rather than presented as a newly introduced regression. Match the final read explicitly: discard genuinely gone/changed processes, but propagate resource failures. This scenario was established by control-flow inspection, not fault injection into the full scan.

**SHOULD-FIX — Namespace lookup becomes quadratic.** `finding:w8-review7-procfs-cache-complexity`; `crates/tidemark-fs/src/procfs.rs:349`.

`cache.iter().position(...)` searches every prior namespace. N PIDs each in a distinct namespace incur N(N−1)/2 key comparisons; 10,000 namespaces require 49,995,000 comparisons before descriptor work. Repeated PIDs in a namespace appended late also rescan earlier entries. Such a set can fit comfortably within the byte cap with small mount maps. Use a budgeted index with sublinear lookup. This is an operation-count finding; no host-scale latency benchmark was run.

The remaining error behavior is as follows. `transient()` remains exactly ENOENT/ESRCH/EACCES/EPERM; EIO remains nontransient.
