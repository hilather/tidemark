# SCR-006: Clarify GNU du apparent-size oracle for directory sizes

- Raised by: W0-C    Date: 2026-10-11
- Affects: metric oracle description (no core type, schema or CLI change)
- Docs: 03-link-semantics.md §2–3; 09-testing.md §3
- Affected tasks: W0-C, W1-B, W2-A, W2-C

## Problem

03 defines t_apparent to include directory st_size, but also says it equals
`du -sxB1 --apparent-size`. GNU coreutils 9.11 in this sandbox omits directory
sizes: an empty parent directory with size 60 and empty child with size 40
produced `du -ab` totals of zero. The golden fixture root produced 1,073,156
apparent bytes; the normative reference including measured directory sizes
produced 1,073,636 bytes.

The official [GNU du manual](https://www.gnu.org/software/coreutils/manual/html_node/du-invocation.html)
states that apparent sizes count regular files and symbolic links; other types
do not contribute. Thus the numerical metric definition and equality claim
cannot both hold with this tool.

## Proposal

Keep the normative directory-inclusive t_apparent definition and all frozen
contracts. Clarify the du equality/oracle wording: compare after adding measured
subtree directory apparent sizes on versions that omit them. Probe an empty
owned directory to distinguish behavior instead of assuming a version number.
Special inode apparent sizes may require the same explicit normalization if
future fixtures assign them nonzero st_size.

## Impact if accepted

Later scanner/aggregator tests keep computing directory-inclusive t_apparent.
Only GNU oracle comparisons need normalization. No schema or data migration.

## Interim

W0-C reference retains the normative definition unchanged. du_apparent returns
unmodified GNU output. A separate empty-directory probe reports tool behavior;
the real-fixture test explicitly subtracts measured subtree directory sizes
from the reference only for this comparison. Disk golden values remain exact.
