# SCR-002: Place shared API payload types in core and specify wire typing

- Raised by: W0-B1    Date: 2026-10-10
- Affects: core/API contracts    Docs: 08-interfaces.md §2; wave-4-lvm-deploy.md W4-A, W4-B
- Affected tasks: W0-B2, W4-A, W4-B, W5-D, W6-A

## Problem

Core must provide all typed API payloads, but StatusResult references ComponentState from a future daemon module and LvmResult references VgInfo from tidemark-fs. Both crates depend on core, so importing these definitions into core creates cycles. The API table does not define Rust widths, request id types, names of params structs, or non-UTF-8 root wire encoding.

## Proposal

Use core::api::{ComponentState, VgInfo} as the shared definitions, copying the exact W4 field lists. W0-B2 and future owners should re-export these at the documented downstream paths. Use u32 for protocol version, String for request ids/methods, serde_json::Value for untyped envelopes, and ApiError { code: ApiErrorCode, message: String }. Response.result/error are optional and omitted when absent; codes serialize as the documented snake_case values.

Freeze the named *Params / *Result types in crates/tidemark-core/src/api.rs. Result collections use aliases to the exact normative live types. Limit is usize; uptime_s u64; sampled_at i64; mount and grouping labels are String. HotWindow permits only 1m/5m/15m/60m; HotBy only dir/unit/comm. Scan mode and throttle use Auto/Walk/Bulk and Gentle/Normal/Max enums. Root query fields use RawPath and its byte-array serde representation, preserving non-UTF-8. The human-readable path/path_b64 object remains available through RawPath::to_json for rendered reports. No-argument params use empty objects. Request.params remains required.

## Impact if accepted

No method or error-code rename. W0-B2/W4 owners re-export shared types instead of duplicating them. W6-A and CLI clients must agree on root byte-array encoding; this is currently unspecified by the plan and needs an explicit decision before implementation. If conventional UTF-8 strings/path_b64 objects are preferred, change RawPath's wire adapter or params adapters together.

## Interim

Implemented the above in core only, without modifying downstream stubs. API tests consume both documented JSON examples and check error-code spelling and omitted optional response fields.
