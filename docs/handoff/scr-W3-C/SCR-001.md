# SCR-001: Allow sibling store modules to stream snapshot rows

- Raised by: W3-C    Date: 2026-10-11
- Affects: Snapshot internal query access. Docs: 05 §3/§10; wave-3 W3-C
- Affected tasks: W1-E, W3-A, W3-B, W3-C

## Problem
Snapshot owns a private `conn` in reader.rs. No connection/path accessor or per-directory streaming file query exists. Its public `subtree_files` collects a Vec (up to one million FileHits), including descendant files. The exporter cannot meet streaming notable-file requirements through that API without a bounded temporary workaround. Editing reader.rs is outside this attempt's owned paths.

## Proposal
Add `pub(crate) fn connection(&self) -> &rusqlite::Connection` to Snapshot. This is internal visibility only, without changing public/core signatures or storage schema. Permit W3-C to use prepared SELECT cursors ordered by directory preorder and raw name for directory and notable-file rows. Alternatively assign a callback streaming query to W1-E.

## Impact if accepted
Coordinator adds the accessor in reader.rs; W3-C replaces public materializing queries with streaming cursors and removes the interim cap. Other query owners can share it. No migration.

## Interim
Export directories individually in preorder and load at most 4097 notable subtree results once. Reject exports above 4096 notable files before emitting output. The bounded list is sorted by directory id/name/ino; unnamed bulk files and multi-link files stay in aggregate entries. No directory tree is collected. This cap is a documented gap, not a claimed contract change.
