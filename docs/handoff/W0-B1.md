## What was built

Implemented all eleven requested core modules: path, units, time, scan, snapshot, live, dev, config, api, json and error. Scanner and live field lists retain the normative names, types and order; snapshot rows cover every SQL column and SnapshotMeta every required key. Byte paths have validated serde round-trips, lexical normalization, component-aware prefixes, terminal escaping, xxh3 hashes and UTF-8/base64 JSON representations. Configuration has strict unknown-key rejection, documented defaults, effective default-alert merging, resource-bounded one-file loading and I/O-free validation. Added typed API envelopes/parameters/results, public rustdoc and fifteen core tests, including the exact unchanged TOML example.

Internal details: decimal size fractions are truncated to whole bytes and limited to 18 fractional digits; overflow is rejected. Size parsing also accepts explicit decimal SI suffixes. fmt_rate uses signed binary units/s and returns "unknown" for nonfinite inputs. Root-parent traversal clamps lexically at `/`; no realpath or filesystem access happens in path helpers. Invalid/out-of-four-digit-range ScanId dates use an epoch prefix, with the original input retained in suffix hashing.

## Known gaps and follow-ups

- SCR-001 through SCR-004 require coordinator/reviewer decisions before declaring the contracts frozen. These are explicit interim implementations, not approved policy or spec changes.
- W0-B2 must build CLI/daemon surface and downstream stubs; shared GateStats, ComponentState and VgInfo locations need re-export agreement. W5-D should reuse/wrap core default_rules after SCR-003 resolution.
- Raw root API wire encoding needs an explicit decision with CLI/daemon owners; no normative root request example exists.
- ScanId's 32-bit suffix is collision-resistant only in a practical, noncryptographic sense; snapshot writers must refuse replacement. No collision-avoidance I/O belongs in core.
- FileHit.path may be None after a bulk name-resolution race; consumers must render this honestly.
- JsonDoc's requested static schema field limits arbitrary owned deserialization; report serialization is supported.
- cargo-deny and platform/VM runtime checks were not run. No core runtime scanning exists in this task.
