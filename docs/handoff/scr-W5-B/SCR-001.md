# SCR-001: Procfs metadata gate and enumeration identity

- Raised by: W5-B    Date: 2026-10-11
- Affects: process scanner/procfs interfaces   Docs: AGENTS.md rules 6/11; 07 §4
- Affected tasks: W1-D, W5-B, W6-A

## Problem
`scan_open_files(devs, want_flags)` owns all procfs metadata I/O but accepts no Gate. ProcScannerOptions likewise has no gate. The existing helper uses std read_dir without O_NOATIME. W5-B cannot enforce these rules through the frozen signature or within its write scope.

OpenFile contains pid but no starttime. The helper validates identity during enumeration, but attribution happens afterwards; PID reuse between enumeration and cache lookup can attribute an earlier file to the replacement process. Cache starttime validation protects its own reads, not the association with OpenFile.

## Proposal
Add `starttime: u64` to OpenFile populated with the validated enumeration starttime. Permit a gate-aware procfs source variant accepting `Arc<dyn Gate>` and charge each syscall, with no-atime directory enumeration implemented in sys. Add a gate field or an explicitly authorized constructor variant for ProcScanner. Compare OpenFile.starttime to Attribution.starttime; mismatch should use explicit unknown attribution.

## Impact if accepted
Coordinator updates shared interfaces and primitive implementation; W5-B adapts the production source. No snapshot migration. Callers need to provide a Gate.

## Interim
Use the frozen helper and shared cache; do not add independent ungated procfs I/O. Unit tests cover fresh attribution between passes. The cross-stage reuse race and gate/no-atime enforcement remain gaps.
