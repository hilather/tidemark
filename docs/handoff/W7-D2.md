## What was built

`cargo xtask man [--out DIR]` defaults to `target/man`, renders the real CLI and daemon clap definitions through clap_mangen, and appends EXIT STATUS, FILES and SEE ALSO sections; the daemon also has SIGNALS. Dates are empty, no hostname is used, and versions come from each command's package version. CLI statuses come from 08 §1.3; daemon statuses reflect `main_entry`/`run_args`, whose startup errors exit 1 and check-config validation errors exit 2. Paths, permissions and signal semantics come from the plan and daemon code; no HTTP feature is documented.

Generated 31 pages: `tidemark.1`, `tidemarkd.8`, and 29 visible CLI command pages, including nested commands. This follows clap_mangen's natural command-tree rendering and avoids dangling subcommand manual references. The generator uses an iterative stack bounded by the compiled command tree.

Pages: `tidemark-{alerts,completions,deploy,deploy-stage,deploy-unstage,deploy-verify,diff,export,export-ncdu,files,hot,links,lvm,now,phantom,probe,scan,snapshots,snapshots-list,snapshots-prune,snapshots-rebuild-catalog,snapshots-show,status,symlinks,top,tui,watch,wide,writers}.1`, plus the two main pages.

All 31 files are explicit RPM assets under `/usr/share/man/man1` or `/usr/share/man/man8`, 0644 root:root, doc=true, sourced from target/man. Native and container build command sequences generate manuals before cargo-generate-rpm. The upgrade fixture receives identical assets and its whole-file drift test still permits only the configuration-source replacement. Operator installation guidance and packaging build documentation describe the manuals.
