# SCR-001: bounded foreground watcher event stream

- Raised by: W5-A Date: 2026-10-11
- Affects: watcher public API; Docs: wave-5-live W5-A, 07 §3.2
- Affected tasks: W5-A, W6-A

## Problem
The frozen Watcher API offers only hot aggregates, completed minutes, dirty directories and stats. None retain the event PID, comm, full path and individual delta needed for the specified foreground event lines. The CLI also has no tidemark-sys dependency and cannot create a separate fanotify consumer without a forbidden manifest edit.

## Proposal
Add `pub struct WatchEvent { pub at: i64, pub path: RawPath, pub delta: i64, pub attribution: Attribution }` and `pub fn drain_events(&self, limit: usize) -> Vec<WatchEvent>` on Watcher. Retain at most 1,000 recent events with a dropped-line counter. Alternatively authorize a callback/channel constructor specifically for foreground use.

## Impact if accepted
W5-A can render at most 50 lines/second with an omitted-event summary; W6-A need not consume this stream. No core or schema change.

## Interim
Implemented standalone minute summaries, signal-driven shutdown and exit-code 5 preconditions. Per-event lines and their rate limiter remain unimplemented rather than fabricating PID/path information from aggregates. Existing public method signatures and option fields are unchanged.
