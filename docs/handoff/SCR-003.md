# SCR-003: Clarify config defaults, profiles and alert rule representation

- Raised by: W0-B1    Date: 2026-10-10
- Affects: core config contracts    Docs: 08-interfaces.md §3; 07-live-monitoring.md §6.4; wave-1-primitives.md W1-D; wave-5-live.md W5-D
- Affected tasks: W0-B2, W1-D, W2-C, W4-B, W5-D, W6-A

## Problem

The example and alert field table define values but not Rust fields/types, generated default rule names or subjects, or precise required-versus-optional rule-specific fields. W1-D explicitly supports user-defined throttle profiles whereas 08's example/CLI lists only gentle/normal/max. W5-D assigns default_rules(cfg) to the live task but also says the config layer merges defaults; core cannot depend on live.

## Proposal

Freeze the interim config implementation:

- ConfigIssue is { field: String, message: String }; the field is a dotted location, and returned issues are validation errors.
- Config and its table structs use deny_unknown_fields. Paths are PathBuf, size fields ByteSize, ordinary duration fields Duration with humantime-serde, bounded counts u32/usize, percentages/latencies f64. Root mode and link_instances use enums; root throttle is a String and throttle.profiles a BTreeMap<String, ThrottleProfile>. Existing gentle/normal defaults are merged with supplied profile overrides; max remains the reserved no-throttle selector. API/CLI enum presets remain limited to the three documented choices.
- Absent roots use both example roots. RootConfig's absent window is None; the built-in /data root explicitly sets its example window. Missing config files return the original I/O error so the CLI can apply built-in defaults as 08 §1.1 directs.
- AlertKind is an enum. above is Option<AlertThreshold>, where the untagged threshold is Number(f64) or Text(String); below, window and older_than are Option<String> interpreted during validate. This preserves duration-or-size, duration, and duration-or-auto fields without inventing config keys. Optional path/glob/count/percent fields follow the table; name and kind are required. enabled=true, for_=5m, resolve_for=10m. The type keeps for_ renamed to for.
- Rule-specific field requirements are the exact table usage sets: mount/above for fs_used_pct and phantom_bytes; mount/below/window for time_to_full; mount/path/above/window for hot_dir_growth; data_above/meta_above for thin_pool_pct; below for vg_free_low; root/depth/above for dir_growth; above for pg_wal_bytes/pg_slot_retained; window for pg_archiver_failing; older_than for scan_stale; mount/above/window for watch_lossy. vg/pool are optional applicable globs with effective '*'. Unused supplied fields are rejected, including on disabled rules.
- Move the pure default_rules(cfg) implementation to core::config; W5-D may wrap/re-export it. All eight default kinds from 07 §6.4 are enabled, with listed thresholds/windows and default 5m/10m hysteresis unless 07 explicitly gives a different firing duration. Filesystem and phantom rules expand over sampler.mounts; watcher rules over watch.mounts. Base names are fs_used_pct, fs_full_soon, phantom_bytes, watch_lossy, pg_slot_retained, pg_archiver_failing, scan_stale, thin_pool_pct. The primary mount (/data if present, otherwise first sampler mount) gets the base name; other mounts append ':<mount>'. User rules override equal names; duplicates among user rules survive merging for validation.
- Config::default and Deserialize produce effective defaults; merge_default_rules is idempotent. Config::load reads only one file, capped at the documented 1 MiB MAX_CONFIG_BYTES constant.

## Impact if accepted

No keys or example text change. W1-D can accept custom profile names. W5-D should use core defaults and interpret the threshold/string fields as validated. W0-B2 and W6-A display the effective rule set. Default rule naming, scope and required fields need coordinator approval before freezing.

## Interim

Implemented the proposal and tests for exact example round-trip, unknown keys, default override/merge, custom profiles, missing rule kind, duplicate names, invalid windows/paths/fields, missing files and input size cap. No socket_group exists; ADR-018 is reflected by the current plan and implementation.
