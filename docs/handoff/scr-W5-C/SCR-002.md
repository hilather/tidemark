# SCR-002: Label refresh has no clock for retry backoff

- Raised by: W5-C    Date: 2026-10-11
- Affects: PgCollector::path_labels    Docs: wave-5 W5-C, 07 §5.2
- Affected tasks: W5-C, W6-A

## Problem
Collection methods take injected `now: i64`, but frozen `path_labels(&mut self)` does not. The general failure/backoff wording also covers daily label-refresh queries. A precise failure timestamp cannot be obtained in that method without calling a system clock inside otherwise deterministic collector logic.

## Proposal
Add `path_labels_at(&mut self, now: i64) -> Result<Vec<(RawPath, String, String)>, PgError>` for daemon refreshes, retaining the existing signature for compatibility. The timed method would consult and update the same backoff state as timed collection methods.

## Impact if accepted
W5-C adds the timed method; W6-A calls it when scheduling label refreshes. No config or schema migration.

## Interim
`path_labels()` remains read-only, bounded, version-checked and safely initialized, but returns errors directly and does not modify retry/unreachable timestamps. Fast and relation collection methods implement backoff and unreachable state using their injected clocks. No system-clock call was added to the library.
