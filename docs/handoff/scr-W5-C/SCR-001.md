# SCR-001: Clarify the PostgreSQL credential-file DSN contract

- Raised by: W5-C    Date: 2026-10-11
- Affects: PostgreSQL DSN configuration    Docs: 07 §5.1, 08 [postgres]
- Affected tasks: W5-C, W6-A, config/documentation owner

## Problem
The task requires a password file named in config, but PostgresConfig has only a DSN. The plan names libpq's `passfile=` option, which the synchronous Rust postgres client does not parse itself. The plan does not specify whether pg.pass is a raw password or libpq pgpass records, nor URL-form passfile handling.

## Proposal
Document keyword-form DSNs with `passfile='/etc/tidemark/pg.pass'`, absolute paths only. Permit root-owned mode-0600 regular files up to 4096 bytes containing either a raw one-line password without colons, or standard five-field pgpass records (escaped colon/backslash, wildcard matching). Require an explicit user and one host/port for pgpass matching. Inline DSN passwords are rejected. Decide whether URL-form DSNs with passfile need support or a dedicated `password_file: Option<PathBuf>` should be added to core config.

## Impact if accepted
Documentation/config-validation owner clarifies accepted DSNs. A dedicated key or URL passfile support would require a follow-up. No schema changes.

## Interim
W5-C extracts passfile from keyword-form DSNs with libpq-style quoting/backslash escaping, validates the opened descriptor without following a final symlink, and supplies the selected password to the synchronous client. Missing configured files fail; no configured file means peer/no-password authentication. No fixed credential path or environment-derived password is used. URL DSNs without passwords continue through the client parser; URL passfile options remain unsupported. Connection/query errors never include DSNs or passwords.
