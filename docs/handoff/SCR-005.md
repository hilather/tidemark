# SCR-005: Error-free signatures cannot return a not-implemented error

- Raised by: W0-B3    Date: 2026-10-11
- Affects: cross-task stub return behavior; no proposed core/schema/CLI/config changes
- Docs: wave-0-foundation.md W0-A deliverable 3 and Cross-task stubs; wave-1-primitives.md W1-A–E; 05-storage.md §3; wave-4-lvm-deploy.md W4-A; wave-5-live.md W5-D
- Affected tasks: W0-B3, W1-A–E, W4-A, W5-D

## Problem

Wave 0 requires every cross-task stub to return Err(NotYetImplemented). The normative later-wave signatures include Option, Vec, String, plain structs, tuples, f64, constructors returning Self/Arc, and unit-returning methods. These cannot return an error without a signature change. Snapshot::meta returns a borrowed SnapshotMeta; a fieldless Snapshot cannot satisfy that accessor safely. gate_from_config returns the existing core ConfigIssue struct, not a crate error enum, so it cannot return a NotYetImplemented variant either.

Examples: mount_for_path -> Option<&MountInfo>, probe -> ProbeReport, bulkstat_probe -> BulkstatSupport, ag_ino_range -> (u64, u64), AdaptiveGate::start -> Arc<AdaptiveGate>, controller_step -> f64, root_slug -> String, retention_plan -> Vec<String>, lvm_now -> LvmNow, slope_bytes_per_sec -> Option<f64>.

## Proposal

Keep all normative function signatures unchanged. Clarify the Wave 0 rule with this exception:

“Result-returning stubs return Unsupported/NotYetImplemented. For a specified Result<T, ConfigIssue>, return the existing ConfigIssue with message NotYetImplemented. Error-free signatures return inert/unknown placeholders without I/O, callbacks, threads, or panics. Option returns None; Vec/String returns empty; capability booleans return false; ranges return an empty range; the controller returns NaN; rates/statistics return unavailable/zero values; plain constructors produce inert objects; unit methods do nothing. BulkstatIter emits one Unsupported error then terminates. space_check_with returns Refuse with reason NotYetImplemented. Snapshot retains a private metadata field for meta(), while open() still returns NotYetImplemented. The placeholders are not implementations of the owners’ runtime acceptance criteria.”

No core type change or new public signature is proposed.

## Impact if accepted

W0-B3 can preserve final cross-task signatures. Later owners replace the inert bodies and expand name-only/private shapes. Callers must not interpret plain placeholder values as successful discovery; collectors/openers already fail explicitly. The documented root_slug collision/injectivity behavior remains W1-E implementation work. No storage migration is needed.

## Interim

W0-B3 retained every signature and used exactly the inert behavior described above, with tests of each body and a handoff table of error-free functions. No frozen core contract was changed. ConfigIssue uses field "throttle" and message "NotYetImplemented". Gate implementations return rate 0 and acquire does nothing; they are not operational throttle gates, and gate_from_config returns an error. LvmNow has empty identities, zero required numeric fields, None for optional values, and the injected report timestamp. Independent review must decide this exception before treating the task as verified.
