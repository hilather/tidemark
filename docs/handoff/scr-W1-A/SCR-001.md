# SCR-001: Non-filesystem mount roots cannot inhabit RawPath

- Raised by: W1-A    Date: 2026-10-11
- Affects: MountInfo.root contract    Docs: wave-1-primitives.md W1-A; 13-contract-decisions.md SCR-004
- Affected tasks: W1-A, W1-B

## Problem
Linux mountinfo includes valid nsfs records whose root is `net:[4026533000]`, rather than an absolute filesystem path. The current sandbox exposes such a record at `/run/docker/netns/ce5afda2b2ea`. `MountInfo.root: RawPath` cannot represent it because RawPath rejects nonabsolute inputs. Rejecting this one record makes all mount discovery unknown; discarding it would miss a real mount boundary. A fabricated absolute root would misrepresent the kernel record.

## Proposal
Change `MountInfo.root` to a task-owned enum `MountRoot { Path(RawPath), Object(Vec<u8>) }`, preserving decoded kernel bytes. Keep `mount_point: RawPath`, and keep all query signatures unchanged. Consumers interested in subdirectory bind roots explicitly match Path. Add serialization only if needed later.

## Impact if accepted
Coordinator authorizes and coordinates the field-type change with W1-B and other MountInfo consumers. No core path, snapshot or CLI contract changes.

## Interim
Preserved the frozen field type. Parsing returns an explicit error on this valid but unrepresentable record; probe emits explained unknowns without panicking. Regression: `nsfs_nonabsolute_root_requires_contract_decision`. Mount discovery on namespaces containing such records remains incomplete.
