# Handoff — W6-A1: Daemon lifecycle and live services

## Needs from coordinator

This is an evidence candidate with the following integration limitations, not a declaration of verified completion:

- `tidemark_fs::lvm::collect(&LvmConfig, now)` provides per-child deadlines but no cancellation hook. Lifecycle returns a deadline error rather than blocking past its nine-second join budget; an in-flight LVM worker can remain alive in an in-process caller until collection finishes. A cancellable collector is needed to guarantee both prompt shutdown and joining every worker with arbitrary configured LVM timeouts. No reporting commands ran on this workstation.
- W6-A2 needs a collector source for exact watcher windows. The existing `Watcher::hot` accepts integer minutes, retains approximate/top-K buckets, uses its own clock, and `WatchStats` exposes only cumulative overflow counts. A1 provides `Publication::WatchWindow` for complete, exact-duration observations; unsupported/unpublished/stale windows return `None`, never a rounded window or fabricated zero. A coordinator-owned live-library follow-up is needed for arbitrary Duration windows and complete inventories. This is a seam request under R2-10; library/plan/SCR files were outside this attempt's permitted paths.
- The store library does not expose an alert-history reader. `alerts_history` currently exposes only up to 10,000 successfully persisted events observed during this daemon run; it does not recover earlier events after restart. A store query seam is needed for the persistent API history contract.
- Storage calls use the retained directory's `/proc/self/fd/<fd>` path and no-follow artifact inspection. The existing store implementation still opens SQLite leaves/header files using pathname APIs and performs recovery internally. Full leaf-level no-follow guarantees, including protection against same-uid leaf substitution between inspection and opening, require a store-owned fix. No store files were edited.
- W6-B should use `snapshot_metrics_handle() -> Option<Arc<SnapshotMetrics>>`. The preparation's owned `snapshot_metrics() -> Option<SnapshotMetrics>` remains unavailable: its non-Clone cache cannot be copied without changing B's type. The shared handle preserves the actual published cache and does not require changes to any currently compiled stub caller.

`LiveState` is Clone and Default. A view snapshots state/config under one lock; referenced watchers/scanners retain their own collector locks. `config()` returns the effective config and monotonic generation: A2/B poll it at service boundaries and restart/reconfigure their owned components when it changes. `wait_service` wakes on generation changes or shutdown. The effective config always includes literal state-dir scan exclusion and state-dir watch/procscan prefix exclusions. State directory and socket relocation require restart and are rejected without replacing config. Sampler and LVM poll the generation themselves. Watcher publishers must release their own handles and call `remove_watcher` before restart; final Arc drop stops the underlying watcher.

Publication retains:


Publish `Procscan` only after a successful pass, and `WatchWindow` immediately before evaluating `view_at(measured_at)` with the exact rule duration and a complete inventory. `None` denotes unavailable; `Some(empty)` denotes measured empty. No rounding is performed. Config reload invalidates window facts. Component health does not imply a measurement publication.

Caps: `MAX_SUBJECTS=128` mounts/roots/components/degraded reasons; `MAX_INVENTORY=10_000` inventory entries/history events; `MAX_WINDOWS=1024` window or root/depth pairs; `MAX_FS_SAMPLES=7201` per mount with additional two-hour timestamp eviction. Over-cap complete publications fail rather than silently truncating. Raw samples at duplicate seconds replace in-memory values; rollback clears a ring. Sampler samples at every configured interval and persists at most one observation per mount/second because the storage primary key has whole-second precision. The writer deduplicates filesystem and LVM gauge keys within batches and against existing rows, including across restart; the first persisted observation wins.

Message variants remain exactly the preparation payloads: `ScanStarted(ScanEntry, Sender<Result<(), DaemonError>>)`, `ScanFinished(ScanEntry, Sender<Result<(), DaemonError>>)`, `Fs(Vec<FsSample>)`, `Lvm(Vec<LvmSample>)`, `Hot(Vec<HotMinute>)`, `Phantom(Vec<PhantomSample>)`, `Writers(Vec<WriterSample>)`, `Alert(AlertEvent)`, `DirSeries((RawPath, String, i64, Vec<DirRow>))`, `Flush(Sender<()>)`.

`CHANNEL_CAPACITY=64`; `MAX_BATCH_ROWS=20_000`. Producers chunk to that row cap, use `try_send`, and report dropped persistence on full/disconnected queues; they never wait indefinitely. Filesystem batches combine up to the row cap, flushing on idle/barriers. Scan acknowledgements carry errors. Legacy `Flush(Sender<()>)` acknowledges barrier completion; writer health carries persistence failures because its ack has no error payload. Failed fs batches are discarded after reporting rather than poisoning future flushes. Compaction reads the current retention config hourly with an injected clock. Lifecycle uses a separate writer shutdown flag, joins producers, sends the flush barrier, then stops/joins the writer.

## Assumptions and deviations

- Existing state directories are conservatively refused unless already private 0700 and owned by the daemon uid/gid (root:root in production), even if marked. New directories use 0700. No uid-0 requirement was added.
- Reused the existing private deployment file helper via a path module, matching firstboot's existing reuse. A narrowly documented duplicate-module lint allowance avoids editing its owner files.
- SQLite code classification uses the exposed error code's Debug names (`DatabaseCorrupt`, `NotADatabase`) because adding a direct rusqlite manifest dependency was forbidden. Other errors never trigger recovery.
- Journald is used when `INVOCATION_ID` is set and its layer is available; otherwise stderr is used. Main holds no stderr lock throughout the daemon lifetime, so worker logging is not serialized behind a lifetime-long lock.
- Unix socket binding returns EPERM in this sandbox. The binary test exercises real startup, readiness/stopping log evidence, SIGTERM and successful exit here; it additionally asserts READY/STOPPING datagrams when binding is available. Actual notification transport remains pending an unrestricted environment. The sandbox uid is 0; tests use temporary paths and no root-only operations, but a nonzero-uid run is not evidenced here.
- Persistent-history, exact watcher query, store leaf confinement, legacy cache adapter and cancellable LVM limitations are explicitly listed above; no frozen core contracts or library APIs were silently changed.
