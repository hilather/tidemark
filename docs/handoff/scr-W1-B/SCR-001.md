# SCR-001 — bounded threshold candidates

- Raised by: W1-gate-fix-walk; Date: 2026-10-11
- Affects: WalkConfig candidate contract; docs: `03` §4 Step G, `04` §2.2/7
- Affected tasks: W1-B, W2-A/C

Status: proposal; implementation uses the task's authorized safest bounded fallback.

## Problem

Step G in `03` §4 keeps every threshold candidate up to global `max_notable`. Frozen WalkConfig exposes no `max_notable`, so no bound expressed solely by `top_files` can preserve this separate class: with top_files=0, arbitrarily many entries can still qualify. Adding a contract field is outside this task.

## Interim

Implemented fallback: at most 4,096 threshold candidates per directory; the next qualifying entry returns WalkError::Limit, aborting the scan rather than silently dropping a required candidate. Completed scans preserve exact threshold selection. This can refuse scans with wide directories, including many empty files when threshold=0. Existing million-entry refusal remains separate.

## Proposal

Requested downstream decision: pass a global max_notable bound to the walker, or introduce bounded spilling/chunks. Taking each directory's first max_notable candidates in normative order would preserve the capped global result. No frozen contract was modified here.

## Impact if accepted

W2-C supplies the bound and W1-B consumes it; W2-A retains normative global selection. No storage migration is required.

## Decision (coordinator)

Pending. The current bounded refusal is expressly authorized by the assigned task, not approval of the proposed contract extension.
